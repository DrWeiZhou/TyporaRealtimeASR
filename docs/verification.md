## 联调中修复的问题

- 旧 WinMM `waveInOpen` 无法打开本机设备：改用 WASAPI 采集原生格式，WDL 有状态重采样为 16kHz 单声道，按真实采样时长截断补齐尾部。
- 正常停止后的静音尾部被恢复为未识别内容：持久化处理位置，区分正常处理过的静音与崩溃时未提交的音频。
- Typora 重开文件后把注释解析为 paragraph：适配器识别独立段落注释与 HTML 注释节点，排除代码块。
- 保存与插入不能原子提交：引入 applying 持久化意图，模糊状态进入人工确认，避免无条件重放。
- 单会话工作任务停止时可能遇到队列关闭边界：关闭输入后重新检查持久任务队列，再退出工作循环。

## 实现范围与限制

- 这是可使用的 Windows 首版，固定 Typora 1.14.10；不是跨版本稳定的官方 Typora API。
- 初版使用带认证的 500ms HTTP 轮询，尚未实现 WebSocket。
- 原始 PCM 连续写入每个会话的独立文件，尚未实现分卷轮换或自动清理。
- VAD 使用能量门限；强噪声、重叠发言、连续长句需要继续现场调优。强制分段文本默认需要确认。
- 中文输入法自动测试覆盖 composition 事件；真实输入法候选窗、多种输入法软件仍需人工验收。
- 尚未完成真实连续两小时录音、噪声环境对照、跨版本兼容、真实断电、系统休眠恢复、硬件拔插、磁盘满等破坏性/长期测试。
- 首字 P95、句尾 final P95、真实访谈准确率尚未建立统计，不能用合成音频的 RTF 替代。
- 不支持同时由多个编辑器改同一文件；已观察到磁盘冲突时暂停补写，但不声称能阻止所有外部程序覆盖文件。

测试文档位于 `artifacts/editor-probe.md`，没有用用户原有的访谈记录进行写入测试。录音测试数据均保存在本项目内。
