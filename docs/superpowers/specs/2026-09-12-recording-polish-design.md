# 录音控制与在线润色设计（已确认）

## 目标与方案选择

实现暂停续录、麦克风电平、服务一键启动、明确保存状态，以及带时间戳的原始逐字稿和在线 LLM 润色后入文。

推荐服务端持久化润色队列：本地识别 → 保存原文 → 在线润色 → 保存润色结果 → Typora 插入 → 磁盘保存确认。相比插件直接请求 LLM，该方案在关闭 Typora、网络失败和重启后更容易恢复。整场录音结束后统一润色延迟过大，不作为本期主流程。

## 录音与界面

- 暂停停止采集，并将当前尾句提交识别；后台继续处理已有音频。续录沿用同一会话、文档和逐字稿，不建立新记录。结束后禁止续录，重启恢复会话默认不自动打开麦克风。
- 保存每次录音区间的墙上时钟起止时间与音频样本偏移。暂停时间不计入有效录音时长，时间戳仍可还原实际发生时间。
- 电平条显示当前输入的 RMS 与峰值；暂停归零。持续低电平显示“暂未检测到声音”，避免将安静误判为设备故障。
- 面板提供启动服务按钮，调用固定项目启动脚本，隐藏后台窗口。分别显示模型和转写服务的启动中、就绪、失败状态；防重复启动，失败可重试。
- 独立显示录音状态、识别/润色待处理数量、待写入数量、Markdown 保存中/已保存/失败与最后确认时间。音频保存与文档保存分开，不把接口返回成功当作磁盘保存成功。

## 原始逐字稿和时间戳

- SQLite 原文为不可变事实记录；每个片段包含稳定 ID、会话 ID、音频起止偏移、实际时间、原始识别文字。
- 单独导出逐字稿 Markdown，每段显示 `[00:01:23–00:01:29]` 和实际开始时间，头部注明日期与时区。该文件由服务管理，区别于人工编辑的目标 Markdown；界面提供查看/导出入口。
- 不对既有历史逐字稿伪造实际发生时间：缺少历史时钟数据时只显示音频偏移。
- 润色内容默认附带对应时间范围，便于回查原文。人工修改目标 Markdown 不反向修改原文或已保存润色结果。

## 在线 LLM 配置与队列

- 设置界面支持 OpenAI 兼容 Chat Completions API：Base URL、模型、API Key、润色提示词、连接测试。默认不预填厂商或真实密钥；其他协议不在本期自动适配。
- API Key 在 Windows 当前用户下加密存储，界面掩码显示，不写入 Markdown、日志或发布包。配置测试只发送固定测试文本。用户在本机界面填密钥，无须发给助手。
- 默认提示词只允许修正错字、标点和口语表达，保留事实、姓名、数字、不确定性，不增加总结或推断。
- 每个确认片段单独润色，按原始顺序插入。初版优先低延迟与可恢复性，不做整篇反复润色。提示词和模型配置版本随任务保存；配置修改不重写已入文内容。
- 原文先持久化，再请求在线 API；不发送音频、整篇人工笔记或其他会话内容。时间戳由程序保管并附加，不依靠 LLM 生成。
- 润色未配置、请求超时、限流或失败时保留原文并显示待润色；有限自动重试后允许手动重试。禁止悄悄以原文替代润色结果自动入文。前段失败时后段等待，保持顺序。
- 已成功润色并持久化的任务在恢复时复用结果，不重复调用。远端成功而本地尚未保存即崩溃时可能重复请求，无法承诺远端恰好一次计费。
- LLM 输出作为纯文本插入，不执行模型返回的 HTML 或指令；继续保留现有事件去重、IME 延迟、撤销、文件冲突暂停和人工修改保护。

## 验证范围

- 暂停时刷新尾句，连续多次暂停续录无丢句、重句或时间回退，结束后录音句尾与润色队列正常排空。
- 合成音频测试电平和静音归零；实际麦克风检查显示与录音控制。
- 模拟 API 验证鉴权、提示词、超时、限流、重试、响应为空、重启恢复与有序插入。真实在线验证需用户本机配置有效 API。
- 检查密钥不出现在状态接口、日志、文档、导出和发布包中。
- 重跑人工修改保护、撤销、中文输入期间延迟写入、保存失败、恢复去重测试；验证未润色内容不会误入文。
