# 窗口润色（低延迟、按大意分段）

## 问题

1. 旧流程要求每个窗口累计 300–1000 字，并且同一会话同时只允许一个窗口在润色。模型较慢时，待润色的片段会越积越多（曾达到 11 段），文档写入间隔经常超过 30 秒。
2. 程序要求模型输出 JSON 并自行判断“话题”（`new` / `continue`、标题、话题列表），效果不理想。
3. 去掉话题后，每个小窗口都会单独成段，同一个大意被拆成多段。

## 现在的做法

1. ASR 逐段识别，原始逐字稿照常导出（不变）。
2. `Ledger.CutWindows` 在片段识别完成后几乎立即切窗，并在 `events.win` 上记录所属窗口。满足以下任一条件就切窗：
   - 累计达到 60 字（`WindowMinChars`），在 60–400 字范围内优先在停顿最长的片段边界处切；
   - 最早一段识别完成后已等待 3 秒（`WindowMaxWaitSeconds`）；
   - 会话已暂停、已停止或未加载，且 ASR 队列已清空（由 `Program.cs` 传给 `PolishPipeline` 的 `flush` 判断）。

   每个会话最多同时有 3 个未完成窗口（`MaxOpenWindows`）。只有达到上限时，新片段才会继续累积，最多合成 400 字（`WindowMaxChars`）的窗口，避免排队越积越多。
3. `PolishPipeline.Run` 最多同时请求 3 个窗口（`MaxConcurrent`）。模型较慢时，后面的窗口不必等前一个完成。结果仍按说话顺序写入文档：`ReadyEvents` 遇到未完成（包括重试中）的窗口会停下，后面的结果等它完成后再写入。
   - 目标：两次写入间隔不超过约 15 秒。组成是：ASR 分段（连续说话时每段最长 12 秒）+ 识别约 1 秒 + 切窗等待最多 3 秒 + 模型请求时间。面板显示的“上次润色 X 秒”过长时，应换用非推理的快速模型。
4. 请求内容：
   - 系统提示词：用户配置的提示词，后面追加 `PolishFormat.Contract`（约定输入标记、段落用空行分隔、接续标记，以及无有效内容时输出“（无）”）；
   - `<上文>`：文档当前的最后一个段落，只作参考、不输出。它由上一个窗口的最后一段，加上前面被接续的内容拼成；超过 600 字时保留开头 200 字（主题句）和结尾 400 字。上一个窗口仍在润色时，使用它的原文；
   - `<待整理>`：本窗口的原始文本。
5. 按大意分段：每段只讲一个大意，第一句为主题句。模型先判断 `<待整理>` 开头是否与 `<上文>` 属于同一个大意、是紧接着的内容：
   - 是：第一段以“【接续】”开头，只写接续的内容，不重复上文，也不写主题句；
   - 否：直接开始新段落。后面出现的新大意各自另起一段。

   `PolishFormat.Parse` 去掉代码围栏、输入标记和接续标记后，按换行拆成段落。只有存在上文时才接受接续标记。输出只有“（无）”这类括号占位时，窗口标为 `deleted`，不插入任何内容。
6. 结果以 `{"paragraphs":[…],"continues":true|false}` 存入 `polish_windows.result`。`ReadyEvents` 在窗口最后一个片段的 `seq` 位置输出一个窗口事件，事件 id 为 `win:{session}:{first_seq}`，并带有 `paragraphs` 和 `continues`。
7. 插件写入规则：
   - 每个新大意是一个新的有序列表项 `N. 段落`；
   - 接续段会并入上一次插入的列表项（同一步撤销），前提是该列表项仍是文档最后一块，且没有被手动改过；否则作为普通段落追加，不占用新序号。
8. 请求失败时按 3、6 秒退避重试；同一窗口 3 次都失败后，面板显示审核卡片，可“插入原文”、“忽略”或点击“重试润色”。手动重试不会影响正在请求中的窗口。

## 兼容性

- 旧版本以 `{"blocks":[…]}` 存储的结果仍可读取：各块的段落依次输出，原话题标题作为单独一段放在该块前面；第一块为 `continue` 时按接续处理。
- 旧的 `polish_topics` 表在服务启动时删除。
- 旧会话中已有逐段润色结果（`polish` 表）的片段仍按原样输出。

## 可调参数

`Ledger.WindowMinChars`、`WindowMaxChars`、`WindowMaxWaitSeconds`、`MaxOpenWindows`、`PolishMaxAttempts`，`PolishPipeline.MaxConcurrent`，以及 `PolishFormat.MaxContextChars`。
